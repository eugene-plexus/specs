## What real clients found

Hermes's first authenticated run completed two file reads, then failed with
`messages[2].reasoning: is not supported`. It replays assistant reasoning under
`reasoning`, while Eugene accepted only `reasoning_content`. The gateway now
normalizes the alias without losing the text. Four regression cases failed
before the fix. Conflicting non-null aliases and invalid types are rejected
with the original field name; values are not reflected in errors. The actual
Hermes task then passed.

OpenClaw's custom model needed explicit `compat.supportsReasoningEffort: true`
for the selected level to appear on the wire in this installed release.
An earlier successful run omitted effort, so it did not count as effort
acceptance. The Keys recipe now includes that flag and
`compat.supportsUsageInStreaming: true`; it explains that a reasoning model
also needs `reasoning: true` to expose thinking controls.

Two fixture setup failures are not product defects: Hermes's environment key
needed its matching `OPENAI_BASE_URL`, and Cline's private provider record
needed the timestamp and explicit config directory. The final Hermes run
also uses the recipe's `model.api_key` configuration. The fixture's first
driver config used `strata` instead of `strata_local`; it was corrected before
any counted run.
