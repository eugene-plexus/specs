# Eugene Plexus v0.4.0

This release brings encrypted connections between machines, key and passphrase changes, folder access for Workbench without a terminal, pictures from tools for models that read images, more Workbench memory and document controls, more inference settings, and file storage for API clients. It includes all completed work since v0.3.0.

Versioned Windows and POSIX installers, a component manifest, the Python dependency lock and checksums are available in the [GitHub release](https://github.com/eugene-plexus/specs/releases/tag/v0.4.0).
The Linux amd64 container is `ghcr.io/eugene-plexus/control-plane:v0.4.0`.

**Update the root and its standbys first.** See [Updating](#updating).

## Encrypted connections and root recovery

Connections between updated machines use pinned TLS. Automatic mode still permits HTTP to older machines until every machine supports encryption. Model files read through SMB use the share's own encryption settings.

Browsers and apps can use HTTPS on their existing ports. Trust the install's certificate authority on each device, or supply your own certificate. Python clients can need a separate certificate-bundle setting. Plain HTTP stays available until the owner disables it.

Machine keys change yearly by default. Machines also have a change button. An offline machine keeps trusting its old key list until it reaches the root again.

Machines learn a promoted root's address automatically. Sessions from before promotion need a new sign-in. Home reports a promoted root that restarted locked.

## People and keys

The owner can change Eugene's passphrase from People. Sign-in keys change every 90 days by default. The owner can also change them immediately. See Updating for standby and session limits.

Client keys show their last use to the minute. Rotate makes a replacement with the same limits. Both keys share their allowance during the overlap, which defaults to one day. Stop now removes the overlap. Existing requests can finish.

Workbench hides a removed person's data after confirmation from the root, normally within an hour. It deletes the data after 30 days by default. The owner can keep it, export it or delete it immediately. If Workbench learns of three or more removals at once, it waits for the owner to confirm them. Everyone can export their own data. External memory-server deletion can fail; Workbench reports the cause.

Groups can set the threshold for summarising long chats. A person in several groups gets the largest threshold. Workbench shows which groups set it.

## Folder access for Workbench

On a Windows service or a Linux system install, Workbench runs in an account of its own. The owner can now give that account access to a shared folder from Workbench's app page, as Read only or Read and write. No terminal step is needed. Remove takes back only what Eugene added; permissions set by hand stay.

Eugene never changes some items on its own: entries it did not add, a file that has another name outside the folder, and a pipe, socket or device. For each one, the console asks the owner to remove it or keep it. When Workbench cannot open a folder, it says so and links to the page. Eugene refuses drive roots, system folders, its own folders, home folders, links and network paths, and names the reason.

Where Workbench runs in Eugene's own account (per-user installs, Linux `--user` and macOS), it already reaches what Eugene reaches, and the page says so. Folder access was checked on real Windows and Linux systems.

## Workbench memory and projects

- **Past chats:** search earlier exchanges, or let a chat retrieve them. Retrieval is off by default. Connections need a separate permission to search chats, also off by default.
- **Learning:** choose which models suggest or keep notes. No measured model met the reliability bar for Keep automatically. Model-proposed merges require approval. They are enabled for models you set to Keep automatically.
- **Sources:** notes can link documents, cited web pages and selected tool results. Changed documents prompt Still true?. Web sources are checked again only when you ask.
- **Projects:** keep chats, notes, documents and folders together. Project notes stay in their project. General memory is on by default and can be turned off. Set a project's model for new chats.
- **Memory servers:** connect a server beside built-in notes. Send my past chats starts only when you choose it. It excludes project chats, memory-off chats and exchanges that resemble secrets. Stopping leaves already-sent exchanges on the server.
- **Hindsight:** install an experimental memory server from the catalogue on Linux. Choose its model before it starts. Each person has a separate bank.

## Pictures from tools

A model that reads images now sees the pictures its tools return: a browser tool's screenshot, a chart a tool drew, or a photo from a Job Site folder. Before, Workbench showed them only to the person. A picture of up to 5 MiB now passes through a Job Site and a direct MCP server; before, a site's whole answer was capped at 70,000 bytes and a direct MCP server's at 2 MiB.

The gateway carries tool pictures the same way on all three doors. An OpenAI chat caller may now put a picture in a `tool` message, as Anthropic and Responses callers already could in a tool result. Tool pictures count against the request's picture limits (12 pictures, 5 MiB each, 10 MiB a request by default). The newest are kept, after the person's own pictures. A picture over a limit becomes a line in the tool's text that says why it is not attached. The person's own pictures are never dropped.

## Long chats and documents

Workbench summarises earlier turns at 80% of the model's context by default. It keeps the originals and shows the summary. The chat's own model writes it unless another local model is configured. Context windows below 8,192 tokens are too small for this summarising path. Attachments can still leave too little room.

Whole-document questions read long documents in parts automatically. The limit is three documents and 40 parts. Failed parts are named. Settings can require a click before reading.

Scanned-page reading needs a configured vision model and the person's opt-in. The default limit is 200 pages per document. Its accuracy depends on the model. PDF citations can open a rendered page with the passage marked. Workbench says when it cannot find the passage there.

## Reading and answer versions

Name answer versions, compare them, or delete a branch. Deletion hides it for 30 days with Undo before permanent removal. Kept notes stay.

Display controls set text size, width, theme and speaker labels in this browser. Reasoning renders as Markdown and starts collapsed. Tool-result artifacts, revision comparisons, pie charts and stacked bars are supported. A chat can disable automatic artifact runs.

Rich content was checked in Firefox and WebKit. Real Safari and iOS remain unchecked. A looping preview can freeze a Firefox or WebKit chat; close the tab to recover.

## Models and inference

- **Prompt caches:** set llama.cpp's system-memory cache, moved-text reuse and checkpoints on a profile. Left unset, the cache is a quarter of the system memory the model leaves free, up to 64 GiB. vLLM CPU cache offload is opt-in and requires a build that offers it. Memory checks count cache reservations.
- **Drafting:** Discover and the Library recognise DFlash, DSpark and EAGLE3 companions. Companion drafting stays off until selected or measured by the settings builder. No live speed or memory measurement was completed for these additions. EAGLE3 checks used synthetic headers. vLLM now supports head, companion or repeated-text drafting. Repeated-text drafting is on by default, but a chosen head or companion takes precedence. Live vLLM measurements remain unrun.
- **Repeatability:** Same answer every time is off by default. llama.cpp serves one request at a time with it on. vLLM uses its batch-invariant mode. GPU llama.cpp and vLLM repeatability and speed remain unmeasured.
- **Serving capacity:** Measure people served tests one running model copy and records tok/s and first-token delay. The checks used a stand-in engine. The physical-machine sweep and captured-session comparison remain unrun.
- **Hardware:** inspect GPU links, power limits and available health readings. A runtime can restart on remaining cards by default if it still fits. Missing-card recovery was checked with simulated hardware.
- **Strata:** prepare ordered GPU splits and choose experimental speed projection. Projection is off for new preparations and can change answers. Checks used stand-in preparation and processes.
- **DeepSeek V4 Flash:** Eugene recognises its memory layout and can supply a missing V4 chat template for llama.cpp. Checks used fixtures, without a live model run. That fallback does not cover V4.1 or Flash-0731.

Repetition protection still defaults to Observe. Stop remains opt-in because measured rules missed loops and stopped legitimate repetition. Control-token escaping is on by default for user and tool content sent to local models.

## Library files and outages

Move profiles to a model's new location after fingerprint checking. Unproven matches require confirmation. Keep an Ollama model in the Library by linking or copying it, including from another machine. Copying needs space; a hard link shares the existing bytes.

During a Library outage, gateways retain saved model settings across restarts. Workers can start recorded local copies when the source folder cannot be checked. An old copy without a source record cannot do this.

Unified-memory fit counts memory other programs use and respects the GPU limit. Physical Mac validation remains unrun. CPU starter choices can use measured speed: Qwen3.6-35B-A3B reached 13.85 tok/s on one Ryzen 9 9950X. That figure does not predict another machine's speed.

## Model APIs and stored files

Apps can request roles such as `role:chat` instead of a model name. The owner orders models for each role across the install.

The new core `store` component keeps OpenAI-compatible Files and Uploads and Anthropic files. Clients can reference their own PDF, image or UTF-8 text files in requests. Files stay until deleted unless expiry is configured. Removed people's files follow the configured removal retention. Defaults allow 10 GiB and 10,000 files per owner. File references share the 11 MiB inference attachment budget. Rotating a client key currently starts a separate file owner.

Responses accepts client-run custom, shell and patch tools. Custom grammars are not enforced. Compaction returns a summary item for later requests to the same gateway. The SDK checks used a stand-in backend.

Gemini clients can use generateContent, streaming, tools and token counting. Unknown Gemini model names use the Chat role by default. Safety settings are reported as ignored. Checks used the real Python SDK with a stand-in backend and replayed CLI requests.

## Open WebUI

Open WebUI 0.12.3 uses Eugene's web search and image models. Search uses provider snippets. Reset to Eugene's settings applies newly available models.

Updates keep one recovery copy. Go back restores it and loses changes made after that copy. Update, Reset and Go back remain unavailable for Linux installs that give the app its own systemd account.

## Other changes

- Rename machine display labels, navigate the console tree by keyboard, search settings from the header, and choose runtime names from a list.
- Local scans detect truncated GGUF tensors before launch.

## Updating

Update in this order:

1. **The active root and every standby.** Newer machine reports carry fields an older root refuses.
2. **Every other machine**, with **Machines → Versions → Update all**.
3. **Workbench**, which is a separate app update even when you update the container. Update all includes it; otherwise update it from **Apps**.

Containers update through Docker or their NAS controls; pull the v0.4.0 image.

The update installs `store` automatically. On restart, the active root adds and starts it beside the gateway. No separate installation or exposed port is needed.

Workbench migrates its database to schema **33** on first start. It keeps `workbench.sqlite3.schema-<N>.bak` beside it, where N is the previous schema. It refuses a newer schema. Going back needs compatible software and a matching data copy. Removing a person's data also purges these migration copies, so they cannot recover that person's deleted data. Back up a stopped installation; see the [installation and recovery guide](https://eugeneplexus.com/install/#update).

For v0.1 installations, start v0.3.0 once before updating. The agent, control and Library no longer convert their retired v0.1 data. Workbench still migrates its v0.1 schema.

Update standbys before changing the passphrase or retiring sign-in keys. Standbys replicate the passphrase change and require the new passphrase for promotion. A locked machine that was offline can ask for the old passphrase once. Replace any passphrase file reported as old. Downgrading an agent after a passphrase change is unsupported.

After an emergency sign-in-key change, Workbench asks for sign-in within five minutes. Open WebUI sessions continue until expiry or sign-out. Paste rotated client keys into external apps; Eugene updates managed app key files. Rotating Open WebUI's app key resets its settings.

The previous [v0.3.0 release limits](v0.3.0.md) still apply.
