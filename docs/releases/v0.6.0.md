# Eugene Plexus v0.6.0

This release brings one fair queue in the gateway, Prometheus and OpenTelemetry export, checked engine updates, a gateway restart that finishes its answers, a tray Pause for a machine's models, Tavily search and remote MCP on the Responses API, and a fix for containers that stayed locked after a restart. It includes all completed work since v0.5.0.

Versioned Windows and POSIX installers, a component manifest, the Python dependency lock and checksums are available in the [GitHub release](https://github.com/eugene-plexus/specs/releases/tag/v0.6.0).
The Linux amd64 container is `ghcr.io/eugene-plexus/control-plane:v0.6.0`.

**Update the root and its standbys first, then every gateway.** See [Updating](#updating).

## One fair queue in the gateway

A request over its key's concurrency limit now waits instead of getting a 429. By default, 8 requests may wait for each key and person. The key still runs at most its limit at once, across every gateway.

Requests for a busy local runtime now wait in the gateway, not in llama-server. They leave by priority, then by person in turns, then by arrival. One person's burst no longer holds back another person. A request for a runtime that is starting waits for it, up to **Start-on-demand wait**, instead of getting an immediate 503.

Priority is Interactive, Background or Dropped first when busy. A key's editor sets it, beside **Requests that may wait** (0 refuses at once, as before). A permission group's queue band replaces the key's priority for a signed-in person. The `X-Eugene-Band` request header can lower a request's priority and never raise it. Workbench's memory learning and tidy pass now use Background. On a busy machine they wait behind chats, and a refused pass is tried again at the next pass.

Each request keeps room for its answer in the model's shared context. The room is the length of the conversation's long answers (95 in 100 are shorter), or 4,096 tokens for a new conversation. It is never below **Smallest room kept for an answer** (1,024 tokens by default) and never above the request's `max_tokens`.

Refusals name their cause: the key's line is full, the gateway's line is full, a more urgent request took the place, the wait ended, the runtime is still starting, or the gateway is restarting. Callers get a 429 or 503 with `Retry-After`, or Anthropic's `rate_limit_error` or `overloaded_error`. The Metrics page shows **Waited in line**, the requests waiting for each runtime, and the refusals by cause.

Two behaviours change:

- After **Longest wait in line** (60 s by default), a request waiting for room moves to its slot's next target if it has one, and is refused if not. The next target can be a paid cloud account. The Metrics page counts each move. Before, such a request went to the busy engine after 120 s.
- Requests beyond the slots a runtime reports wait in the gateway. An engine that reports no slots is not held back.

Limits:

- Fairness is per gateway. The root enforces only each key's limits.
- A key has no owner yet. A key with no verified person is one person for the queue. Open WebUI sends no person token, so its users share one turn.
- CI checked the queue with a stand-in llama-server. The prompt-cache measurement and the speed sweep on a real llama-server did not run for this release.

## Metrics for Prometheus and OpenTelemetry

The gateway and each agent serve `GET /metrics` in Prometheus text on their own ports. The agent's page carries each running engine's counters, labelled `node`, `runtime`, `model` and `engine`. A counter the engine lacks has no series. It is never a 0.

A scraper signs in with a client key that has **May read metrics**, or with an operator session. No credential gets a 401. A key without the grant gets a 403. On Metrics, **Export** makes a scrape key and copies the scrape configuration for every machine. The scrape key can run no model and no tool.

Every metric name starts with `eugene_`. The names are new in this release. No metric has a person's name. Series per key are on the Prometheus page only. A request with a made-up model name makes no new series.

OpenTelemetry export is off by default. Set **Send metrics and traces to** in the gateway's settings to an OTLP/HTTP address. Eugene sends counters, timings and one trace for each request, as JSON. It never sends a prompt, an answer, a key name or a person. The Metrics page shows whether the last send worked and why not. A failing collector never stops a request.

Other changes:

- Counters come from the request store. With **Retain request metrics** off, they stay empty, and `/metrics` says `eugene_metrics_enabled 0`.
- `/v1/systemone` decisions now write request rows, with door `decisions`.
- `GET /v1/metrics?bucket=hour` serves hours past retention from the stored hourly summaries. They have counts, mean and maximum latency and mean tok/s, without percentiles. Hours summarised before this release have zero in the added columns.
- llama-server now always starts with `--metrics`. Before, only drafting added it. This opens `/metrics` on each llama-server's own port. It shows counts, not prompts or answers.

Not run: a real Prometheus server and a real OpenTelemetry Collector. CI used a stand-in llama-server and a stand-in OTLP receiver. No check scraped a real llama-server or vLLM through Eugene.

## Checked engine updates

**Update on the Engines card now updates the models running on that machine, one at a time.** Before, it only installed a build. An install now stages its build, and the build in use changes only when an update moves the models. **Update all** now also moves each machine's managed llama.cpp, one machine at a time, so a model's copies on other machines keep serving.

For each model, Eugene drains it and starts it again on the new build. The runtime leaves routing, and the restart waits for the answers in flight. After 120 s the rest are cut, and the console says how many. A model with one copy restarts at once, and its requests wait in line. A model with other copies moves only while they carry the load.

Eugene measures the new build against the old one for at most 4 models, when that costs nobody anything: the model's other copies carry the load, it was idle for 600 s, or no gateway routes to it. It measures prompt and generation tok/s with llama-bench and the share of the same top token. **The numbers are shown and never block an update.** A new build can carry a security fix.

A build that cannot load a model, crashes or answers with an error is not used for that model. The model stays on its old build, and the page says why. Other models move. The card's **Use** button for the previous build (for example **Use b11719 again**) moves the models back to it with no download. An update is saved, and an agent restart resumes it. While one runs, an engine install or uninstall is refused.

Not run: the measurement tools on real hardware. The checks used stand-in llama-bench and llama-perplexity tools and a stand-in llama-server, on Linux. No speed or agreement figure for a real build comes with this release. Routing by predicted time to first token is not in this release.

## Gateway restart finishes its answers

A gateway restart or stop now finishes the answers in flight, for up to **Answers finish on a restart for** (120 s by default). New requests and requests in line get a 503 `shutting_down`. A stream still open at the limit ends with an error frame that says it was cut. Before, a restart exited after 500 ms.

The agent drains its gateway before every stop, with a short-lived token of its own. When the agent itself stops, it waits at most 20 s, because a service manager waits no longer. A gateway too old to drain is stopped as before. The drain checks ran on Linux. On Windows, CI ran service restarts and sign-in with the drain in place, but no check measured a drain there.

## Pause a machine's models

On Windows, the tray icon has **Pause models (frees the graphics card)** and **Resume models**. Pause stops every model on that machine and cancels a running benchmark or settings build. Eugene keeps running. The console, the gateway, Workbench, cloud accounts and other machines keep serving. Answers in progress on that machine stop at once.

While paused, nothing starts a model there: a request, Run, a benchmark or a reboot. A request for a model that only this machine serves is refused, and the message names the pause. This needs the model to start on demand. For any other model, the gateway says none of its runtimes asked to be started on demand. A pause lasts through a reboot until someone resumes. Resume starts the stopped models through memory admission and names each one it could not start.

The tray holds no credential. It talks to the agent over a local named pipe, and Windows decides who may connect. An account that may stop the Eugene service may pause its models. The console has Pause and Resume on Machines for every operating system. They need an operator session. A client key or a gateway token is refused. An older agent has no pause, and its card shows no button.

CI ran the tray's own call as unelevated local accounts on a GitHub Windows runner. It covered an account with the stop right, an account without it, a remote pipe path, a program that holds the pipe's name, and a service restart. The checks call the pipe. They do not click the icon, and they did not run on a physical desktop.

## More tools run by the server

**Tavily** is a new search provider. Add it as a search account in the console, with its key and basic or advanced depth. No Tavily key was available for testing. The provider follows Tavily's API reference, and CI used a stand-in.

**Remote MCP** works on the Responses API. A request may carry an `mcp` tool with `server_url`, `headers` or `authorization`, `allowed_tools` and `require_approval`. Eugene lists the server's tools, lets the model call them and asks for approval where the request says so. An approval runs once. Only Streamable HTTP servers work. The tool runs in a search account's process. An install with no search account refuses it and says to add one.

By default, remote MCP reaches the internet only, over `https`. The tool driver resolves the host once, refuses private, loopback, link-local, carrier-grade NAT, multicast and cloud metadata addresses, and connects to the address it checked. The setting **Remote MCP from API clients** has Off, Internet only and Internet and this network. The last is for experts: a client could then reach services on your network through Eugene. Loopback is refused in every mode. A public address of this machine counts as the internet. Remote MCP never uses your proxy, so an install that reaches the internet only through a proxy cannot use it.

A key that limits tools must allow `mcp`. A local-only key is refused. The caller's headers and tokens exist for one request. They are never logged, never in metrics and never in a stored response. Each call has 30 s and 8 MiB in all. A server may list 64 tools, and a response may make 20 calls.

The tool driver no longer logs each request's URL at INFO. That log held a SearXNG search's query text and an MCP server's path and query.

A second model reviewed remote MCP and found no way past the address check. Its two blockers are fixed: one caller's cookies reached another caller's calls, and a session end was read without a size limit. CI ran remote MCP against a fixture server on the runner's own private address. No third-party MCP server was tried.

## Containers unlock after a restart

A container with a passphrase file now comes back after a restart with no sign-in. The agent, which has no file of its own, reads the control root's file named by `EUGENE_PLEXUS_CONTROL_PASSPHRASE_FILE`. Before, the agent stayed locked and a provider account lost its saved API key until someone signed in again.

A new container install needs only that variable. Setup puts the agent and the root on the file and says the file is the operator's. Type the passphrase that is in the file. Setup tests that the file would unlock the agent, and shows one line if it would not. Setup never writes the file, but the control root writes the new passphrase to it after a passphrase change, if it can. A read-only mount keeps the old one.

We confirmed the restart fix on a live root in a container on 2026-11-06. CI checked a fresh container install, restarted with no sign-in. A fresh install was not run on a live host.

## Other changes

- **Hindsight on newer Linux:** systemd 257 and later mount an app's state directory without the right to run programs. Hindsight's database failed to start there, for example on Ubuntu 26.04. The app unit now allows programs in that app's own state directory. The grant covers every catalogue app's own directory. Workbench, Open WebUI and the folder broker did not run on systemd 257 or later in CI.
- **OpenRouter:** models whose listing names no `temperature` or `top_p`, such as Claude 5.5 and GPT-6, no longer fail with "No endpoints found" when a request sets `max_tokens` or tools. A setting the caller sets is still refused with a 400.
- **Inference driver:** a start no longer logs a false "no master key" warning for a sealed key. `httpx` is now a declared dependency. Installs from the release lock already had it.
- **Starter model review:** its CPU speed proof fetches the `.tar.gz` Linux build that upstream ships. The `.zip` it asked for gave a 404. The next review has not run.
- **macOS 14:** GitHub no longer runs macOS 14 jobs, so CI no longer tests it. The installer still runs there, and macOS 14 stays supported. It is not tested. macOS 15 and 26 are tested.
- **Edge:** Edge now publishes once its container image is verified, and full CI does not hold it. Release qualification keeps every gate.

## Updating

Update in this order:

1. **The active root and every standby.** A standby one release behind loops on a key record that has `May read metrics`. Update standbys before you make the first scrape key. A key with a priority or queue bound that is not the default reaches an older component that refuses fields it does not know, and its requests fail. Update the root and every gateway before you change either. A key at its defaults is answered as before.
2. **Every gateway.** A gateway one release behind refuses a key with `May read metrics` for inference. A key without it is answered as before. An older gateway also does not report answers in flight during an engine update. The agent stops waiting for it after 60 s and names it. Update every gateway before you update engines.
3. **Every other machine**, with **Machines → Versions → Update all**. It now also moves each machine's managed llama.cpp.
4. **Workbench**, which needs a separate app update. Update all includes it; otherwise update it from **Apps**. Its only change is the Background priority for memory learning.

Containers update through Docker or their NAS controls; pull the v0.6.0 image. A container install set up before the passphrase file has two Security mode fields, the control root's and the agent's. Set both to the passphrase file. See the [container guide](../deployment/container.md#unattended-unlock).

The gateway's request-metrics store moves from schema **13 to 15** in place on first start. It keeps its history and makes no copy. A gateway from v0.5.0 that opens a v15 store moves it aside as `metrics.v15.bak` and starts empty. Workbench keeps schema 34, and the store component keeps schema 2. Back up a stopped installation; see the [installation and recovery guide](https://eugeneplexus.com/install/#update).

A Linux system install gets the app unit change on update. A running app keeps its old sandbox until it restarts, so restart Hindsight afterward.

The previous [v0.5.0 release limits](v0.5.0.md) still apply.
