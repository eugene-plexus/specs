# Eugene Plexus v0.3.0

This release brings people management and external sign-in, checks each
person's access on every model request, adds speculative decoding for
llama.cpp, records host history, and lets Workbench suggest notes and share a
person's notes and documents with other apps. It includes all completed work
since v0.2.3.

Versioned Windows and POSIX installers, a component manifest, the Python
dependency lock and checksums are available in the
[GitHub release](https://github.com/eugene-plexus/specs/releases/tag/v0.3.0).
The Linux amd64 container is `ghcr.io/eugene-plexus/control-plane:v0.3.0`.

**Update the root and its standbys first.** See [Updating](#updating).

## People and administration

- **People** lists every account with search, filters and pages, and each
  person opens in an editor for account details, groups, app access and
  administration.
- The owner can name administrators with separate grants: managing accounts,
  defining groups, and assigning members within a scope. A delegate cannot grant
  administration, reset passwords, change sign-in identities or alter other
  administrators. Revoking a delegate ends their current session at once.
- Group definitions can change existing members' app and site access. A
  delegate's scope is limited to 64 groups.
- **Access history** shows the owner the latest 50 access changes. Only the
  latest 1,000 records are kept; failed sign-ins and refused changes are not in
  it, and changes from before this release are not attributed.

## Each person's access on every model request

Workbench model requests are now checked against the signed-in person's
current access, not only the app's key. Removing someone's access ends their
running answer within about ten seconds; the measured case took 9.996 s, and
work already sent to an engine cannot be undone. Access proofs last ten
minutes, so a very long answer can end when its proof expires. If the root is
stopped, new model requests are refused until it returns. Other API clients keep
app-only limits until they adopt the same proof.

## Sign in with Google, Microsoft or OpenID Connect

The owner can register Google, Microsoft or any OpenID Connect provider and
link existing members through one-use invitations. Accounts are never merged by
email address. Workbench and administration share one browser sign-in, with
connected accounts, sessions, sign-out everywhere and local password recovery.
The sign-in address is derived from the console's address unless you set one.

You register Eugene with the provider yourself. Sign-in was tested against a
standards-conformant test provider with real signatures; live Google and
Microsoft accounts were not tested.

## Two hostnames on one port

The console and Workbench can be served on two HTTPS hostnames from one port,
with an optional model API at `https://eugene.<domain>/inference/v1` that has
its own network rules. The model API is off by default. Existing setups are
unchanged, and an old hostname keeps working until you choose to remove it.

## Speculative decoding for llama.cpp

The Library shows what each model can draft with: its own multi-token
prediction head or a companion draft model in the same folder. Discover offers
those companions. Reuse of repeated text runs without extra settings. On one
RTX 5090 with one prompt, a model's own head raised 265.8 tok/s to 318.8 tok/s;
the companion model tested was slower than plain decoding. Memory allowances
for drafting are measured on that one machine, not guaranteed.

## Host history

The new **Hosts** page shows each machine's GPU memory and other readings over
time, with gaps where a machine was off. Recording can be turned off or
deleted, and Settings shows its disk use (about 8 MB at the default
retention). Linux and AMD readings are tested only against simulated hardware.

## Workbench

- **Suggested notes:** Workbench can suggest notes from your chats. They quote
  your own words, wait in an inbox, and become notes only when you keep them.
  This is on by default only for models that met our bar in measurement
  (Gemma 4 E4B and 12B, Qwen3.8-27B, Qwen3.6-35B-A3B); even those made a false
  suggestion in up to 3% of cases.
- **Connections:** other apps that speak MCP can search and read your own notes
  and documents and suggest notes, through a connection you create, limit and
  revoke. The owner cannot see other people's connections or notes, and one
  switch turns every connection off. Tested with the MCP reference client;
  Claude Code, Codex and Open WebUI setup formats are not yet verified.
- **Sorting:** Workbench can re-sort the passages it finds with a served
  sorter, and says when and why it did not. At the default 3-second budget a
  processor-only machine does not sort.
- **Reasoning** headers show reasoning tokens and streaming time. Counts marked
  "(estimated)" come from text length, not a tokenizer.
- A signing decision made while a Job Site was checking in is no longer lost.

## Model API

The Anthropic-compatible endpoint accepts `search_result` blocks and the
`memory` tool for local models. Citations are not produced; a request that asks
for them is answered without them and says so. The local llama.cpp backends now
honour "no reasoning" (`reasoning_effort: none`).

## Other changes

- Strata can prepare models with image input on processor or GPU. Strata and
  MLX remain experimental; Strata image answers are not yet validated on a
  native machine.
- Discover guides a download through to running the model; settings search and
  number inputs are easier to use.
- Bug reports and questions have forms in the specs repository; security
  reports go through private reporting.

## Updating

Update in this order:

1. **The active root and every standby.** Older roots cannot accept the new
   people fields or check person access.
2. **Every other machine**, with **Machines → Versions → Update all**. Machines
   on mixed versions refuse model requests from Workbench until they match.
3. **Workbench**, which is a separate app update even when you update the
   container. Update all includes it; otherwise update it from **Apps**.

Containers update through Docker or their NAS controls; pull the v0.3.0 image.

Workbench's data moves to a new format on first start. It keeps a copy of the
old store beside it (`workbench.sqlite3.schema-<N>.bak`) and does not run on a
store from a newer version, so going back to v0.2.3 means restoring that copy.
Back up a stopped installation before updating; see the
[installation and recovery guide](https://eugeneplexus.com/install/#update).

Data converted from v0.1 is still read in this release. v0.3.1 removes that
conversion, so update any v0.1 installation through v0.3.0 first.

The previous [v0.2.3 release limits](v0.2.3.md) still apply.
