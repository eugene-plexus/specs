# Eugene Plexus v0.2.0

*Draft, 2026-10-10: written overnight for Troy to edit before the tag. Nothing
here is published.*

The second release. Still version 0.2 in the old sense: it works, it is
early, and its known limits are listed below. Start with the
[installation guide](https://eugeneplexus.com/install/).

**Updating from v0.1.0 means updating everything, the root first.** v0.2 is
the oldest version this one works with: the compatibility kept for v0.1
consoles, agents, Libraries and gateways is gone. Update the machine that
hosts the control root (the container on a NAS, or the root machine), then
every other machine (Machines → the machine → Versions → **Update**, or run
the installer again). A machine left on v0.1 is not expected to work with a
v0.2 root. See [Moving to v0.2.0](#moving-to-v020).

## The Library, rebuilt around engines

- **Each engine says what it runs, and the Library judges.** Every model in
  the Library and every result in Discover carries a dot: works here, works
  with another engine, or not here, with each engine's reason and, where it
  can tell, its own fit for this machine. llama.cpp, vLLM, MLX and Strata
  each answer in their own terms.
- **Where to find models is a list.** Hugging Face and any hub that speaks its
  API, each with its own address and token, beside the lists engines publish
  of the models they support. Discover searches them together and answers in
  the list's order, which you set in Settings.
- **Fit is each engine's own.** llama.cpp's arithmetic on the card and system
  memory; vLLM's share of the card; Strata's own setup table on this
  machine's RAM.
- **Delete a model**, any format, from its page: the confirmation lists every
  file and its size first, keeps files another model uses (a projector shared
  by quants, Strata's helper files), and is refused while any machine runs it.

## Strata (experimental)

Strata runs the very large Qwen3.8-Flash-Next
mixture-of-experts models on one consumer card by keeping experts in system
memory. Eugene installs it, prepares its models and runs them:

- **Download and prepare** from Strata's own list in Discover, or **Prepare
  for Strata** on a downloaded GGUF: one action that downloads, runs Strata's
  own setup, and starts the model, with progress in the tray.
- **Run recommends preparing when Strata suits the machine better**: when
  llama.cpp would run part of the model from system memory and Strata's own
  table says it fits, Run asks with *Prepare for Strata, then run* chosen.
- **A prepared model is a Library model**: its files live in the Library, so
  any machine can run it and nothing is lost with a machine; a machine runs
  it from its own copy on a fast drive; the Library says what it is, what it
  was made from, how it runs and what it takes on disk.
- **Drives**: Settings and Strata say when the copy folder is on a spinning
  disk or a network share.
- Limits for v0.2: text only (no images), one GPU, Strata's speed projection
  off; these return after v0.2.

## Running more than one machine

- **A warm standby for the control root**: another machine keeps a current
  copy and can take over.
- Guided HTTPS setup, trusted proxies, and one HTTPS port for the container.
- Machines and Needs Attention show every machine's update status.

## Fixes and changes worth knowing

- Upstream drift fixes across the gateway, drivers and Library (2026-10-03).
- Strata installs on a Windows service install, and a failed setup names
  its cause.
- Run operations survive the browser: closing the tab no longer loses a
  download-and-run.

## Moving to v0.2.0

1. Update the root first (the container: pull the new image; a root machine:
   Versions → Update).
2. Then every other machine.
3. **If your Library's source list was saved with the hub first**, Discover
   now shows the hub's results first: move *Engines' own lists* up in
   Settings → Where to find models.
4. A Strata install made before this release needs reinstalling before it
   prepares a model (its preparation tools now come with it): Backends →
   Strata → uninstall, then install. Prepared models in the Library are
   kept.
5. A Library config file from before the source list (only a hub address and
   token, no `catalogueSources`) now gets the default list: enter the token
   again in Settings → Where to find models.
