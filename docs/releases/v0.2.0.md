# Eugene Plexus v0.2.0

The second release. Start with the [installation guide](https://eugeneplexus.com/install/).

**Updating from v0.1.0:** update the root first, then every other machine. A machine left on v0.1 will not
work with a v0.2 root. Your saved data carries over: model profiles, settings and chats are converted to
v0.2's format the first time v0.2 starts, and the old files are kept as backups. See
[Moving to v0.2.0](#moving-to-v020).

## Workbench: memory, documents and tools

- **Memory.** Notes you keep ("Remember that…"), on a Memory page with export and real deletion. Each
  chat shows exactly what it sent, with a guard for outside models.
- **Documents in a chat.** Attach a PDF, a Word file, Markdown, text, CSV, HTML or code, and any model
  answers from it. The answer names the files.
- **Saved documents.** Keep documents, or a folder you grant (kept in step), and Workbench searches
  them by words and by meaning, citing passages by file and page. When a fast local result sorter
  runs, it puts the best passages first.
- **Toolbox.** Shared MCP servers, local MCP servers and folder tools, with each call approved in
  the chat.
- Answer versions; screens for images, speech, transcription and video; easier reading; shorter
  messages.

## Search models

- The agent runs search (embedding) and result-sorting (rerank) models, and the console offers three.
- One endpoint serves `/v1/embeddings` and the new `/v1/rerank`, which takes Jina, Cohere and TEI
  requests.
- Open WebUI's document search runs through Eugene.

## Tools on every model

A chat model is taken to call tools unless its engine or provider has shown it cannot. A setting a
backend ignores is named in the `x-eugene-plexus-ignored-settings` header instead of refused. So Codex
and Claude Code work with more models, including Gemini, most of OpenRouter's tool models, and Strata.

## Providers

- Add a Google Gemini API account in Backends, with a key from Google AI Studio.
- Add Google Search beside Brave as a search account, using a Gemini API key.
- Set the order web search tries its accounts in (Routing → Web search order), or keep the default.

## The Library, built around engines

- Every model and every Discover result shows whether it runs here, with each engine's reason and fit.
- Where to find models is a list: Hugging Face and compatible hubs, each with its own token, plus the
  engines' own lists.
- Delete a model from its page. The confirmation lists every file, keeps files another model uses, and
  refuses while a machine runs it.

## Strata (experimental)

- Runs the very large Qwen3.8-Flash-Next models on one consumer card by keeping experts in system
  memory.
- Download and prepare from Discover in one action. Run suggests preparing when Strata suits the
  machine better.
- Prepared models live in the Library, and each machine runs its own copy.
- Tools and structured output work.

## Job Sites

Workbench works on your own machines, wherever they are. A machine joins with one command, accepts no
incoming connections, and needs no VPN or cloud service. Each person's tools run as their own account,
with calls signed by keys only that person holds. Risky calls are held for approval, and access windows
close on their own.

## Machines and install

- A warm standby for the control root.
- Guided HTTPS setup, trusted proxies, and one HTTPS port for the container.
- Machines and Needs Attention show every machine's update status.
- A replica whose model is still loading is skipped for another.
- Uninstall works offline: an Installed Apps entry on Windows, a removal app on a Mac.

## Console and Workbench changes

### Console

- **Home.** The machine strip shows memory used and free per card, or system memory, as bars, and
  flags stale numbers.
- **Home.** The Running card links to Backends and shows a crashed runtime's cause as text, not only
  a tooltip.
- **Home.** "Use it from your apps" adds a Codex recipe: its config file, and the key in its own
  variable.
- **Playground.** ElevenLabs voices show by name, not id, and "New" reads "New chat".
- **Backends.** Each runtime row has "Start when Eugene starts", saved without restarting the model,
  and a stopped model says why.
- **Backends.** Uninstall an Eugene-managed engine from its row; models and saved runtimes stay.
- **Backends.** A custom OpenAI-compatible backend has a "Wire protocol" setting for when its
  address is a proxy.
- **Backends.** Busy labels say Starting, Stopping, Restarting or Removing, and "config" reads
  "Settings".
- **Routing.** Priority-list steps are numbered.
- **Metrics.** A "Request outcomes" bar shows requests served and not served, and the percentage
  served.
- **Library.** "Runs as" says if a file is a chat, search or result-sorting model, and lets you
  change it.
- **Library.** A model copied to a machine shows how many of its files are whole.
- **Discover.** It opens on "Works here now"; the format filter adds Works with another engine and
  Everything.
- **Discover.** Results show a count above the rows, and the list stacks above the detail on a
  phone.
- **Settings.** "Nothing matches" has a Clear button, and Discard all says how many unsaved changes
  it will lose.
- **Settings.** Machine settings name the kind of drive a model-copy folder is on: SSD, spinning
  disk or network share.
- **Settings.** Repeated-response protection can be Off, Observe (the default) or Stop, for every
  model, chosen ones, or one Workbench chat.
- **Machines.** Separate Copy buttons for the Windows and the Linux or macOS join command; table
  columns say Status and System.
- **Logs.** The log area takes keyboard focus and shows a line count; empty or filtered logs say so,
  with Clear.
- **People.** Each person's Job Sites permissions can follow the install's defaults or be set
  exactly; each row says which applies.
- **Every page.** For screen readers, repeated buttons name their target, new-tab links say so, and
  failures and loading are announced.
- **Every page.** Real plurals and counts ("1 change", "N of M models"), sentence-case labels, and
  Backends where links said Inference.
- **Every page.** Copy buttons cover folders, join commands, addresses and new app credentials; a
  failed copy says what to do.
- **Every page.** A banner says when the install is in dev mode, with a link to change it in
  Settings.
- **Every page.** The longest explanations are shorter and lead with what happened or what to do;
  every safety warning stays.

### Workbench

- **Chat.** Search chat names (Enter opens the first match), and see recent chats grouped by date.
- **Chat.** The composer keeps drafts per chat, takes dropped files and pasted images, and shows
  which attachment is uploading.
- **Chat.** Jump to latest, local message times, Copy on your own messages, keyboard shortcuts and a
  full Markdown export.
- **Chat.** Tab titles name the open chat, a failed load says why, and screen readers name the
  running dot.
- **Chat.** Ctrl+Enter (Cmd+Enter on Mac) saves an edit, images open full size, and a failed rename

- **Chat.** Sources show their site, plus Google's Search Suggestions, unmodified, when Google
  searched.
- **Chat.** Older messages show their date, and a long file name stays on one line.
- **Chat.** While a model works, Eugene works at the bench in short scenes, and holds still for
  reduced motion.
- **Chat settings.** Each hint and range shows under the field, in tokens, with Save settings and
  Close settings buttons.
- **Chat.** Deleting a chat names it, says its files go too, and starts on "Keep it"; Escape backs
  out.
- **Chat.** The composer says "Ask anything" and grows with its text; the sidebar says "Production

- **Tools.** Each server's command or address and each folder's path has a Copy button.
- **Tools.** A bad arguments or environment field names the wrong JSON, and "Checking" shows only on

- **Job sites.** Unsaved sharing edits show "Not saved yet" with "Save sharing"; the audit list has

- **Every screen.** "Loading Workbench" replaces a blank screen, "No chats yet." waits for chats,

## Fixes

### Console

- Run's whole chain, from download to start, survives closing the tab or a restart and shows
  progress on return.
- Adding LM Studio or Ollama takes an address and an API key, both optional, so token-protected or
  proxied servers work.
- The Claude Code recipe gives the model's real window in tokens, and a reply limit that leaves room
  to compact.
- The Claude Code recipe no longer sets an effort value Claude Code does not document.
- Removing the backend you are viewing no longer leaves the page showing something that is gone.
- A runtime's own driver no longer shows as a separate external backend, with Remove, when the
  gateway's list is missing.
- The Playground shows a gateway failure's whole cause instead of cutting it off.

### Workbench

- Removing an unsent attachment deletes it, so it no longer counts against the chat's size limit or
  locks the chat.
- Workbench and the Playground show a backend's own live token count and speed when it reports them,
  never an estimate.
- "Waiting for the model" no longer stays up through long reasoning; Workbench says Thinking, then
  Writing the answer.
- A length stop now names which cap ended the reply and where to change it, in Workbench and the
  Playground.
- An interrupted upgrade can no longer leave Workbench's chat database half-converted, and Workbench
  keeps a copy of it before upgrading.
- Workbench stays up when it cannot open its chat database, and says why.
- Workbench now says when the chat list cannot load or a chat cannot be created, renamed or deleted.
- The rename and delete boxes fit a phone screen.
- A chat whose model is gone says "This model is no longer available" and asks you to pick another.

### Models and inference

- Codex 0.133 and later work through Eugene; their first request was refused over a new kind of
  tool.
- Claude Code's session titles, memory recall and prompt hooks (structured output) now work through
  Eugene.
- Claude Code 2.1.288 no longer fails on request fields Eugene did not recognize; they are accepted
  and named as ignored.
- Claude Code's advisor tool no longer fails every turn; Claude Code carries on without the
  server-side tool.
- A full context window now makes Claude Code compact and carry on instead of ending the session.
- Eugene's web search asks again, leaving the choice to the model, when a model refuses a forced
  first tool call.
- Web search from Codex and other Responses API clients honors a blocked-domains list and names
  options Eugene does not run.
- Reasoning effort "max" is accepted for the models that take it (GPT-6, OpenRouter's); it was
  refused.
- A prompt cut down to a full window, as with Ollama's small default, is now flagged as truncated.
- A key limited to one request at a time no longer gets a 429 right after an answer ends.
- A speech request for an unlisted voice is refused, naming the voices on offer; OpenAI's speech
  models now list theirs.
- A response header now says when embeddings ignore `dimensions` or `user`, instead of silently
  returning full width.
- An unreachable backend says why: a timeout names the address, port and firewall; a refusal gives
  the backend's own message.
- A backend that answers but serves nothing says so, and the backend list no longer vanishes when
  all are unreachable.
- Claude Code and Codex subscription backends no longer run tools or shell commands on the machine
  hosting them.
- Request text sent to them no longer passes through the Windows command line, where quotes could
  run commands.
- Codex subscription usage counts cached and reasoning tokens once, not twice.
- Model suggestions for Claude Code and Codex backends name today's models, not Claude 3.5 and
  gpt-4o.
- GPT-6 on OpenAI no longer fails with a 400 over temperature and `top_p`; log probabilities go only
  at effort none.
- Models that take tools only on OpenAI's Responses API are no longer offered as tool-capable.
- A request that sets `top_k` or `min_p` goes to a backend that honors them; Ollama silently dropped
  them.
- Ollama gets earlier reasoning where it reads it, tool results in call order, and your key on its
  window check.
- "Confirmed local" now says it does not cover Ollama's cloud models, and names the switch,
  `OLLAMA_NO_CLOUD=1`.
- A frozen llama.cpp server is caught as stalled whatever the stall time; its keepalive pings no
  longer reset the timer.
- OpenRouter models drop off the list after their retirement date, and images use OpenRouter's
  documented route.
- OpenRouter speech instructions and transcription prompts, which it ignores, are refused up front;
  chat sends `max_completion_tokens` as documented.
- ElevenLabs transcription access is checked with its newest model, not a deprecated one.
- A Kev server that requires `KEV_API_KEY` is now seen as ready, and its model list shows.
- Brave search no longer reads a prepaid key's empty monthly window as "monthly quota used up", a
  429 never retried.
- The Brave pacing setting no longer describes a free plan Brave stopped issuing.
- Parallel slots left unset now show what llama.cpp does, 4 slots sharing the context, not 1.
- A model started without a context size now reserves its real memory, so the next model's fit is
  not overstated.
- A model you stopped stays stopped across restarts, updates and reboots; it used to come back.
- A model split across several files is copied whole to a machine's own copy, not just its first
  part.

### Library and Discover

- Fit estimates for sliding-window, Gemma 4 and DeepSeek models are no longer too large, so more
  models show as fitting.
- A rescan never rewrites model profiles; an unreadable profiles file is kept and reported as
  degraded, not read as empty.
- A Library whose saved settings cannot be converted reports it, instead of showing no folders.
- Safetensors downloads now include `tokenizer.model`, so Llama, Mistral and Gemma repos that ship
  only it can load.
- Discover says "already on disk" for a safetensors model you already have.

### Machines, updates and install

- Update re-checks the machine's channel before installing; if the check fails or the target moved,
  nothing installs.
- A control root stopped while saving its state no longer fails to start, and a power cut
  mid-write no longer loses its next change.
- A damaged Job Site rules file no longer stops the site: it refuses every tool and says why.
- Needs Attention clears a notice once fixed, refreshing on your actions, version changes and when
  you return to the tab.
- Machines no longer says "Up to date" beside a version warning, and a failed check is no longer an
  all-clear.
- An engine Eugene cannot install says why in text, and warns only when a model you asked for needs
  it.
- The Edge channel no longer names an old commit as newest when GitHub's list lags, which hid
  updates.
- A machine that starts before the control root keeps trying to announce itself, and re-announces
  when its address changes.
- On Windows, the firewall rule you allowed follows Eugene's ports, so a worker's new backend is no
  longer blocked.
- Join commands no longer fail when the join token begins with "-".
- The installers update an outdated uv, which could write outside the target folder on Windows.
- The installers add the Visual C++ runtime that llama.cpp's Windows builds need.
- Uninstall removes the install's stored key from the credential store, and no longer calls a failed
  cleanup step a success.
- On Linux with an NVIDIA card, llama.cpp now finds its CUDA libraries instead of silently running
  on the processor.
- NVIDIA Turing, A100 and H100 cards on a CUDA 13.0 driver get an older CUDA build, or a
  driver-update message.
- The llama.cpp roll-back list now covers about five days of builds, and stepping back reaches about
  a day.
- AMD (ROCm) builds are found by what each release publishes, and the Snapdragon Linux build is on
  the expert menu.
- A Windows ARM machine with a second GPU is no longer asked for a build that does not exist.
- New MLX installs use mlx-lm 0.32.0, where the adapter path setting, silently ignored before, takes
  effect.
- vLLM install instructions for CPU, CUDA 13, ROCm and Intel (XPU) now name wheels that exist.

### Apps and Open WebUI

- Open WebUI no longer sends document text, image or speech requests to OpenAI, and will not start
  without Eugene's address.
- Open WebUI document upload no longer fails on rate limits: app keys allow 8 requests at once, 600
  a minute.
- Workbench installs in a NAS container (no home folder, as on Unraid) and listens on the
  container's address.

## Moving to v0.2.0

1. Update the root (the container: pull the new image; a root machine: Versions → **Update**), then
   every other machine.
2. If your Library's source list was saved with the hub first, move *Engines' own lists* up in
   Settings → Where to find models.
3. Reinstall Strata before its first preparation (Backends → Strata → uninstall, then install).
   Prepared models are kept.
4. A Library config from before the source list (a hub address and token only) gets the default list:
   enter the token again in Settings → Where to find models.
5. Open WebUI resets its saved settings to Eugene's once, at its first v0.2 start.
6. Open WebUI app keys made earlier keep their old limits until you raise them on the keys page.
7. The old `/runtimes` address and the "cyberpunk" theme name are gone; use `/inference` and the
   Plexus theme.

## Known issues

- **A Claude Code turn reserves its whole answer allowance** (32,000 tokens), so a llama.cpp server with
  a 64k-token pool runs one Claude Code turn at a time. The others wait; they do not fail.
- **With many llama.cpp servers on one machine, a reply can stall** while llama.cpp saves and restores
  its prompt cache. In our tests, 3 turns in 3,808.
- **Strata** runs text only, on one GPU, one request at a time, and its memory fit is unknown.
- **Workbench's sorter**: the default Sort time (3 s) sorts on a GPU, where a question takes about
  0.6 s, but not on a typical CPU, where it takes about 7 s. Its gain was measured on questions
  written for these documents.
- **Job Sites cannot yet copy between machines.** It is designed, and next.
- Brave's rate-limit headers are read as Brave documents them, but we have not seen them from a live
  account.

## Distribution

The release provides `install.ps1`, `install.sh`, `manifest.json` and `SHA256SUMS`. The tag is
annotated. The manifest records the specs commit and every component's commit. Workbench and Open
WebUI install at versions pinned in the agent.

The Linux amd64 image, `ghcr.io/eugene-plexus/control-plane:v0.2.0`, is built from the tag and
published only after its container acceptance passes. Its digest is added to these notes on GitHub.
Python packages, uv, engine downloads and model catalogue data are not pinned.
