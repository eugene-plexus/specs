# Eugene Plexus v0.1.0-alpha.1

The first alpha of the local-inference control plane, for early testers.
This is a **prerelease**, not a stable v0.1 release. Moderated usability sessions
and the remaining hardware verification still matter; publishing this alpha
does not mark those gates complete. Older repository tags belong to earlier
project work and are not this distribution.

Start with the [installation guide](https://eugeneplexus.com/install). The
[GitHub prerelease](https://github.com/eugene-plexus/specs/releases/tag/v0.1.0-alpha.1)
contains `install.ps1`, `install.sh`, `manifest.json` and `SHA256SUMS`.
The manifest identifies the exact specs commit and six component commits;
the UI pin is its built `dist` export. Installer bytes come from committed Git
blobs, so Windows checkout line endings cannot change the published checksums.

## Included

- Two-screen setup, hardware-led model suggestions, Download and run, and a
  first reply on Home.
- Managed llama.cpp engines, model profiles and context-depth benchmarks.
- OpenAI-compatible and Anthropic Messages endpoints, revocable client keys,
  request diagnostics, and existing local or cloud backends.
- Multiple enrolled machines, optional local model copies, remote configuration,
  and the Windows service installer.
- Phone layouts, keyboard focus, reduced motion, and plain-language guidance.

The companion Linux amd64 control-plane image is
`ghcr.io/eugene-plexus/control-plane:v0.1.0-alpha.1`. It runs the services;
GPU inference belongs on an enrolled host. The release's image digest is recorded
in its GitHub notes after the image passes the container acceptance checks.
See the [container guide](../deployment/container.md) for storage, ports,
advertised addresses, and enrollment. Existing NAS users can select this image
tag while retaining their current volumes and settings.

## Verification and boundaries

- Windows and WSL fresh application installs, full model downloads under a
  100 Mbit/s cap, real CPU inference, and independent API requests passed
  [S10 acceptance](../acceptance/s10-download-run.md). These were isolated prefixes
  on an existing host, not clean OS installs or a physical 8 GB GPU test.
- Installer service operations are exercised in Windows CI. Reboot before
  sign-in, physical Mac verification and the friend sessions remain outstanding.
- llama.cpp is acquired through the UI. vLLM must already be installed; the
  experimental MLX branch is not included. CPU inference works but can be slow.
- Use a trusted LAN or VPN for other devices. Complete first-run setup before
  making the console reachable by others.
- The alpha fixes **Eugene source revisions**, not every upstream dependency.
  Python patch versions, Python dependencies, uv, engine downloads and model
  catalogue data can change upstream. This is not an offline or byte-reproducible
  environment. Package versions may still display `0.1.0`; the distribution
  version and source commits are identified by the release manifest.

## Updates, removal and reports

Running this alpha's installer again repairs or reinstalls these same Eugene
revisions; it does not follow `main`. A later alpha will have its own page/command.
Do not use an older alpha installer to downgrade a newer installation. Back up
the installation's configuration and keep the passphrase before moving between
versions. Existing per-user Windows installations require an explicit migration;
read the installer's explanation before using `-Migrate`.

The [installation guide](https://eugeneplexus.com/install#remove) includes removal
commands. Default removal preserves original model files and moves configuration
and logs aside. Downloaded engines and managed copies are retained unless an
explicit purge is requested.

Report problems in [specs issues](https://github.com/eugene-plexus/specs/issues)
with `v0.1.0-alpha.1`, OS, GPU/RAM, the step that failed, and the error text.
Remove keys, passphrases, private paths and prompts from anything shared.

## Maintainer publication

Create an annotated `v0.1.0-alpha.1` tag at the reviewed specs commit; never move
it. Run `scripts/release-artifacts.py --version v0.1.0-alpha.1 --ref
v0.1.0-alpha.1 --output <new-directory>` and attach its four files to a GitHub
prerelease. Build the companion image with the Container image workflow's
`release_tag=v0.1.0-alpha.1` input; it checks out the tag and publishes the exact
image that passes acceptance. The versioned run does not advance `edge`.

The website stores this release's manifest, fetches installers from its immutable
specs commit during the site build, and checks their hashes before emitting the
versioned URLs. It does not maintain a second editable copy of either installer.
Publish the GitHub prerelease and verify its assets before deploying the website.
