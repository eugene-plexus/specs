# Eugene Plexus v0.1.0-alpha.3

The third public alpha. It remains a **prerelease**: not a stable release, and
not a claim of production readiness. Start with the
[installation guide](https://eugeneplexus.com/install/).

**alpha.3 needs a fresh install.** An alpha.2 install cannot be upgraded in
place, because the way machines in an install prove who they are has changed
(below) and the old keys are not converted. The installer recognises an alpha.2
install and says so, with the command that removes it. See
[Moving from alpha.2](#moving-from-alpha2).

## Changes since alpha.2

### A leaked key costs one machine, not the install

- **Every machine has its own token key**, generated on that machine and never
  sent anywhere. The control root publishes a signed list of which keys it
  trusts, and every machine checks tokens against it. A stolen worker key reads
  what that worker could read, until the root removes it from the list. Before,
  every machine held the install's one signing key.
- **On Linux, Eugene runs under its own account by default** (`eugene-plexus`,
  in `/var/lib/eugene-plexus`), so programs you run, an AI agent included, cannot
  read its keys, its environment or its memory. It asks for `sudo` once. It
  reaches your model folders through your group. `--user` keeps the old layout.
- **The Windows install folder is private**: the service and administrators
  only. Before, every local account could read its keys and add files the
  service would run.
- Passphrases are at least 12 characters, and the agent refuses requests
  addressed to a host name it does not serve.

### Joining a machine is one command, from any state

- **Add a node prints one command per shell** that installs Eugene and joins it,
  with a guide to which port is which. Run it on the other machine as it is.
- **The join takes over whatever Eugene is already there.** It stops every
  install it finds and moves each folder aside, deleting nothing. Then it
  installs fresh and joins. If anything fails before the join succeeds, every
  install is put back and whatever was running is started again.
- **A refused token says so**, and says to make a new one on the Nodes page,
  rather than to run the same command again.
- `-Uninstall` (`--uninstall`) finds the install wherever it is, and asks for
  Administrator itself when it needs it.
- A failed Windows install ends with what went wrong in plain words, not a
  PowerShell error record.

### More applications, and more of what they send

- **Codex CLI** works through a new `/v1/responses` door: streaming, tool calls,
  images, reasoning, and keep-alives that carry a slow prefill past Codex's idle
  timeout.
- **Claude Code** gets images, `count_tokens` (counted, never generated), its
  current `output_config`, and `thinking.display`.
- **Reasoning comes back** as `reasoning_content` on the OpenAI door and
  `thinking` blocks on the Anthropic door. Before, it was discarded.
- The local samplers (`top_k`, `min_p`, the penalties), `parallel_tool_calls`
  and `developer` messages are carried to the engine.
- A per-driver stream stall timeout ends an answer that stops arriving.

### The control-plane container can run models

On the processor, or on a passed-through NVIDIA card, with the llama.cpp CUDA
build chosen by the card's compute capability. The GPU is opt-in.

### Console

- Metrics shows time to first token and decode speed separately. The difference
  between the two is the prompt's processing time.
- A Routing page edits model slots with pickers rather than JSON.
- More than sixty fixes across the console, and Playground action icons and
  response times.
- The first-run wizard never proposes a models folder inside `C:\Windows`. A
  Windows service runs as SYSTEM, whose home is in there, and alpha.2 could
  propose `...\config\systemprofile\Eugene Models`.

### Failures that say what happened

When llama.cpp cannot be installed because GitHub could not be reached, the
message now names what actually happened. It distinguishes GitHub's rate limit
(with the time it resets), a certificate problem (the clock, a wrong name, or an
untrusted root), DNS, a timeout, and a refused or reset connection. The agent
also checks GitHub's certificate with the operating system's own verifier. That
verifier fetches a root certificate Windows has not downloaded yet, which is
what failed on a fresh Windows machine before.

### Experimental

- **MLX** (Apple silicon) is integrated with simulated evidence only. No
  physical Mac has run it.
- **Typed decisions** (`POST /v1/systemone`) with a supervised Kev model were
  measured on a Linux CPU. Other accelerators and the hosted Jev path are
  unverified.
- An **optional apps** registry, where each app holds a client key only. No app
  ships in its catalogue.

## Verification and limits

- The exact tagged pins passed Windows and Linux CI, the Pester installer
  suite, and container acceptance before the image was published.
- **The one-command join**, on Windows: the owner's worker rejoined a new
  control root on the first run, 2026-09-26. On Linux, in WSL as a system
  service, joins were run against an unreachable root, a root that refuses the
  token, a clean machine, and a leftover alpha.2 folder. Each ended with the
  machine exactly as it was, and the service running again where there had been
  one. A **successful** Linux join, and a failed join restoring a Windows
  machine, have not been run physically; the latter is covered by the Pester
  suite on real folders.
- Codex CLI 0.130.0 and Claude Code 2.1.207 were run against real local engines
  on the processor. See the [Responses](../acceptance/responses-run.md),
  [images](../acceptance/anthropic-images-run.md) and
  [reasoning](../acceptance/reasoning-and-samplers-run.md) records.
- **Still owed:**
  - models on a passed-through NVIDIA card in the container;
  - a physical Mac;
  - modest-GPU capacity;
  - native Linux unattended boot;
  - the Windows reboot-before-sign-in checks;
  - moderated sessions with people new to Eugene.
- Use a trusted LAN or VPN, and finish first-run setup before enabling remote
  access.

See the [support matrix](../support-matrix.md) for each promise and its
evidence.

## Moving from alpha.2

Nothing converts an alpha.2 install, so this is a new install. You will choose a
new passphrase and make new client keys, and machines that were joined to it
join again.

1. **Remove the alpha.2 install.** Its files are moved aside, not deleted.
   - Windows:
     `& ([scriptblock]::Create((irm https://raw.githubusercontent.com/eugene-plexus/specs/v0.1.0-alpha.3/scripts/install.ps1))) -Uninstall`
   - Linux or macOS:
     `curl -fsSL https://raw.githubusercontent.com/eugene-plexus/specs/v0.1.0-alpha.3/scripts/install.sh | sh -s -- --uninstall`

   **Model files are never deleted.** Any in the install's own models folder
   move aside with it, and the uninstall prints where; that is the Windows
   service's default, `C:\ProgramData\EugenePlexus\models`. Move them into the
   new install's models folder afterwards.
2. **Install alpha.3** from the [installation guide](https://eugeneplexus.com/install/)
   and run the setup wizard.
3. **For each worker**, make a join token on the new root's Nodes page and run
   the command it prints there. It sets the old install aside by itself.
4. **For the container**, select `ghcr.io/eugene-plexus/control-plane:v0.1.0-alpha.3`
   with a **new, empty** data directory. An alpha.2 data directory cannot be
   read.

A recovery checkpoint made on alpha.2 restores alpha.2, not alpha.3.

## Distribution

The [GitHub prerelease](https://github.com/eugene-plexus/specs/releases/tag/v0.1.0-alpha.3)
provides `install.ps1`, `install.sh`, `manifest.json` and `SHA256SUMS`. The
annotated tag is immutable. The manifest records the specs commit and all six
component commits, the built UI export included. That export's join commands
name the alpha.3 installer, so a worker installs the version its root runs.

The Linux amd64 image is built from the tag and published only after container
acceptance passes. Its digest is added to these release notes on GitHub.
Alpha.1's and alpha.2's tags, assets, containers and website installer URLs
remain available.

These pins fix Eugene's source, not every upstream dependency: Python packages,
uv, engine downloads and model catalogue data can change. Component package
versions may still show `0.1.0`; identify the distribution by its manifest.
