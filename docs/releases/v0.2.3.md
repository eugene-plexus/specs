# Eugene Plexus v0.2.3

This release brings interactive content to Workbench, redesigns engine and
gateway monitoring, adds shared account groups, and fixes a Library startup
failure when a model folder is inaccessible. It includes the completed work
since v0.2.2.

Versioned Windows and POSIX installers, a component manifest, the Python
dependency lock and checksums are available in the
[GitHub release](https://github.com/eugene-plexus/specs/releases/tag/v0.2.3).
The Linux amd64 container is `ghcr.io/eugene-plexus/control-plane:v0.2.3`.

## Workbench interactive content

- Open supported MCP Apps inside a constrained sandbox, with explicit approval
  before an app invokes tools. Self-contained apps work; apps needing network
  or device access retain their text fallback.
- Use A2UI forms with saved field values and approved actions. Support is the
  pinned A2UI 0.9.1 forms catalog, not arbitrary JSON or the full upstream catalog.
- Select native or authorized external AG-UI agents in a new chat. Supported
  conversations retain tool activity, state and continuation across reloads.
- Saved interactions respect chat ownership, answer branches and current access.
  Reconnecting does not replay actions, and uncertain external work is not
  automatically retried.

These are declared protocol subsets, not full upstream conformance. MCP Apps
does not support the upstream network-enabled separate-origin proxy. AG-UI does
not yet support client-executed tools, multimodal, reasoning, activity, chunk or
subagent events. See the [capability matrix](../design/workbench-ui-browser-v1.md)
and [browser acceptance](../acceptance/genui-browser-run.md).

## Engine management and gateway monitoring

The Engines overview puts running models and their controls first. Engine
installation details, manual commands and experimental-runtime guidance are
available in expandable sections, with failures kept visible. Long names and
mobile layouts have dedicated browser checks.

Gateway Metrics now includes traffic and outcomes, latency, token usage,
backend capacity, cache measurements, hourly comparisons and retained request
traces. Dials show measurements with meaningful denominators. Partial failures,
stale snapshots, missing measurements and disabled recording remain explicit;
JSON export includes its scope. Host hardware history, alert delivery and SLO
policy are separate future work.

## Shared accounts and permission groups

The owner manages Eugene and Workbench access through the central account
directory. Existing account IDs, chats and individual access are preserved.
Permission groups govern app sign-in and the implemented job-site permissions;
Workbench links its owner to the central directory.

This is U1, the foundation for SSO. Delegated administration and Google,
Microsoft and generic OpenID Connect sign-in are not included. Withdrawing
Workbench access takes effect at its next refresh, within the existing
ten-minute bound. See [account acceptance and rollout](../acceptance/u1-shared-accounts-2026-10-15.md).

## Linux setup recovery

An inaccessible default model folder could crash the Library before its HTTP
listener started. Setup then reported a connection failure and could not browse
for another folder. The Library now stays available, reports the actual folder
error, and permits choosing an accessible folder without a restart. It does not
change filesystem permissions or silently replace the configured root.

The fix was reproduced with a real Linux permission denial. A CachyOS user's
screenshot prompted the investigation; their exact startup cause remains
unconfirmed without logs. See [the reproduction](../acceptance/library-private-home-run.md).

## Updating

Update the active control root and all standbys before using the new group
management controls: older roots cannot replay group operations. Then use
**Machines → Versions → Update all** to update eligible workers and their
catalogue apps, including Workbench. Each machine follows its selected channel.
Containers update through Docker or their NAS controls; pull the v0.2.3 image.

An existing Workbench installation must also update to receive interactive
content and the central-directory link. Back up a stopped installation before
updating; see the [installation and recovery guide](https://eugeneplexus.com/install/#update).
The previous [v0.2.2 release limits](v0.2.2.md) still apply.
