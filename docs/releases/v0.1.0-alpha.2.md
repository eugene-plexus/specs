# Eugene Plexus v0.1.0-alpha.2

The second public alpha brings the completed adoption roadmap to early testers.
It remains a **prerelease**, not a stable release or a general production-readiness
claim. Start with the [installation guide](https://eugeneplexus.com/install/).

## Changes since alpha.1

- Home waits for the model to be ready before enabling Send, and shows actionable
  download, loading and failure states.
- Application request settings are validated consistently. The documented
  Open WebUI and Claude Code workflows were exercised with actual local models,
  including images in WebUI and a confined edit/check task in Claude Code.
- Registered client keys can be revoked and restricted by model, local-only
  routing, request rate and concurrent work. Usage and uncertain outcomes remain
  attributable. WebUI connection keys identify the application, not each employee.
- Local-only policy is enforced through routing and drivers. Failover avoids
  replaying ambiguous work and uses bounded cooldowns and deadlines. Cancelled
  requests release capacity without treating a healthy backend as failed.
- Stopped installations can create encrypted checkpoints with configuration,
  identities, policies, package versions and source revisions. Restores begin in
  quarantine for validation. See the [recovery guide](https://eugeneplexus.com/recovery/).
- Optional driver capability probes have bounded concurrent timeouts, fixing
  cold local-only startup when a managed model is stopped.

See the [application recipes](../application-workflows.md),
[API compatibility](../api-compatibility.md), and
[tested configurations and support boundaries](../support-matrix.md).

## Verification and limits

The exact component pins passed Windows/Linux integration checks and container
acceptance. [A8](../acceptance/a8-shared-load-run.md) exercised real Open WebUI and
Claude Code against CPU-only Gemma 4 E4B on a Ryzen 9950X: twelve mixed-load chats
had p95 completion of 9.25 seconds; both concurrent coding tasks passed. An excess
request was refused in 18 ms, and cancelling three generations freed their slots
in 0.207 seconds. This finite five-client scenario is not a five-user capacity
guarantee or a GPU benchmark. The record includes raw measurements and limits.

Physical Mac, modest-GPU capacity, native Linux unattended boot, remaining Windows
service checks and moderated friend sessions remain open. llama.cpp is managed;
vLLM requires its own installation and environment; experimental MLX is excluded.
Use a trusted LAN or VPN and finish first-run setup before enabling remote access.

## Upgrade and recovery

1. Let active work finish and keep your installation passphrase available.
2. **Upgrading from alpha.1:** its agent cannot create the new checkpoints. Stop
   the installation and its children, then keep a protected complete copy of its
   installation/state, Python and virtual environment. Preserve model files and
   external engine environments separately. Restoring that copy requires the
   original absolute paths. Follow the recovery guide's alpha.1 instructions.
3. **Upgrading from an A7-capable development build:** use the stopped-install
   checkpoint procedure. After upgrading from alpha.1, create and rehearse a new
   checkpoint before relying on it for the following update.
4. Run the alpha.2 installer for the same installation prefix and mode, or select
   `ghcr.io/eugene-plexus/control-plane:v0.1.0-alpha.2` for the NAS while retaining
   its volumes, ports and environment. Update enrolled workers separately.

The Windows default remains a LocalSystem service. Existing per-user installs
need explicit migration; read the installer explanation before using `-Migrate`.
Do not run an older installer over newer state as a rollback.

## Distribution

The [GitHub prerelease](https://github.com/eugene-plexus/specs/releases/tag/v0.1.0-alpha.2)
provides `install.ps1`, `install.sh`, `manifest.json` and `SHA256SUMS`. The annotated
tag is immutable. The manifest records the specs commit and all six component
commits, including the built UI export. Re-running a versioned installer keeps
those source revisions; it does not follow `main`.

The Linux amd64 image is built from that tag and published only after container
acceptance passes. Its immutable digest is added to the GitHub release notes.
Alpha.1's tag, assets, container and website installer URLs remain available.

These pins fix Eugene source, not every upstream dependency: Python packages,
uv, engine downloads and model catalogue data can change. Recovery reconstruction
needs network access before the disconnected rehearsal. Component package versions
may still show `0.1.0`; identify the distribution using its manifest.

Report problems in [specs issues](https://github.com/eugene-plexus/specs/issues)
with `v0.1.0-alpha.2`, OS, hardware, failed step and error text. Remove secrets,
private paths and prompts from shared logs.
